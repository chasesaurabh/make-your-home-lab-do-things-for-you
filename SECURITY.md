# Security policy

The companion has three one-operator local projects. Maintenance effects change only a disposable setting and bundled strings. The inbox organizer copies explicitly selected small text notes after exact approval. The service watcher records configured read-only loopback HTTP observations and performs no repair. Use synthetic or nonsensitive data when learning and reporting defects; keep private notes and their application database out of public reproductions.

Tools have no model-controlled commands, paths, SQL or URLs. Models cannot grant approvals or invoke effects. Approvals bind exact proposal, job, target/version, evidence, policy and expiry. Operator names are audit labels, not authentication. Anyone controlling the OS account or database can bypass the teaching application's rules. Loopback does not authenticate other local users; keep the read-only board off the LAN.

Target receipts are separate from job state. Unknown writes never trigger blind retries. Missing receipts, partial artifacts or failed verification require inspection. Offline snapshots require all workers/board to stop and do not establish consistency against concurrent writers. The lab promises no real-time deadlines, hostile-local-user isolation, physical storage guarantees or exactly-once external effects.

Report ordinary defects with synthetic reproductions in repository issues. For vulnerabilities, use GitHub private vulnerability reporting if offered in the Security tab. If unavailable, open only a non-sensitive coordination issue without exploit details or secrets while arranging a private channel. No paid security support is promised.

Inbox state stores the complete selected note text for exact review and copy verification. A selected local model receives those notes; inspect the server's logging and access controls before using sensitive material. Input, state and output directories must remain under the operator's control. Approval is not authentication against another process with the same OS permissions.

Service reports store URLs, configured markers, observations and body hashes, not response bodies. Choose GET endpoints that are read-only. Socket timeouts bound idle I/O rather than strict total wall time against a continuously responding peer. Loopback binding does not authenticate local callers.

Never add credentials, personal information, private logs, weights, manuscript or production assets to a public reproduction. A successful model run or pattern scan is not security certification.
